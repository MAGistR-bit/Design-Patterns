## 👨‍🦱 Паттерн Одиночка
Паттерн Одиночка направлен на создание уникальных объектов,
существующих только в одном экземпляре.

> Паттерн Одиночка во многих отношениях представляет
> собой **_схему_**, которая гарантирует, что для заданного класса
> может быть создан один и только один объект.

### 📜 Определение паттерна
> Паттерн Одиночка гарантирует, что класс имеет только
> один экземпляр, и предоставляет глобальную точку
> доступа к этому экземпляру.

### 〰️ Многопоточная реализация паттерна
Итак, синхронизация метода `getInstance()` приводит к
значительным затратам ресурсов.

Как усовершенствовать многопоточную реализацию?
1) **Ничего не делать, если производительность `getInstance()`
не критична для Вашего приложения.** Синхронизация
getInstance() – простое и эффективное решение. Только помните,
что синхронизация метода замедляет его выполнение в сто и 
более раз. Если метод `getInstance()` применяется в интенсивно
используемой части приложения, возможно, вам стоит пересмотреть
свое решение.
2) **Создавать экземпляр заранее.** 
```java
public final class Singleton {
    private static Singleton uniqueInstance = new Singleton();
    
    private Singleton() {
        
    }
    
    public Singleton getInstance() {
        return uniqueInstance;
    }
}
```
При таком подходе мы доверяем JVM создание уникального
экземпляра Singleton при загрузке класса. JVM
гарантирует, что экземпляр будет создан до того, как
какой-либо поток сможет обратиться к статической
переменной `uniqueInstance`.  
Потоковая безопасность этого кода гарантирована.
3) **Воспользуйтесь "условной блокировкой", чтобы свести к минимуму
использование синхронизации в getInstance().**
````java
public final class Singleton {
    
    private static volatile Singleton uniqueInstance;
    
    private Singleton() {
        
    }
    
    public static Singleton getInstance() {
        if (uniqueInstance == null) {
            synchronized (Singleton.class) {
                if (uniqueInstance == null) {
                    uniqueInstance = new Singleton();
                }
            }
        }
        return uniqueInstance;
    }
}
````
Сначала проверяем, создается ли новый экземпляр, и если нет,
ТОГДА синхронизируем фрагмент кода. В этом случае синхронизация
будет выполняться только при первом вызове (что нам, собственно,
и требовалось).

> Ключевое слово volatile гарантирует, что параллельные программные
> потоки будут правильно работать с переменной `uniqueInstance`
> при ее инициализации экземпляром Singleton.

Стоит отметить, что условная блокировка не работает
в Java 1.4 и более ранних версиях! При необходимости
использования JVM-версии, отличной от Java 5, 
стоит рассмотреть другие способы реализации паттерна Одиночка.

### 🗝️ Ключевые моменты
1) Реализация **паттерна Одиночка** на языке Java использует
приватный конструктор и статический метод в сочетании
со статической переменной.
2) Будьте внимательны с условной блокировкой – в версиях до Java 5
она была небезопасной.
3) Будьте внимательны при использовании загрузчиков
классов – они могут привести к созданию нескольких
экземпляров, а это противоречит основной цели паттерна.
4) Если вы используете JVM версии ранее 1.2, создайте
реестр синглетных объектов, чтобы предотвратить их
уничтожение сборщиком мусора.
5) Для упрощения реализации "Одиночки" можно воспользоваться
перечислениями Java.
